# Post-Incident Review: records_processed metric returned 0 due to exclusive upper bound

## Summary
The reconciliation job's `records_processed` metric dropped to 0 on 2026-08-19 at 12:57:16 UTC, contrary to the expected range of 150-400 records per nightly batch. Root cause: `IRecordStore.GetRecordsForWindow()` used an exclusive upper bound (`< toUtc`) instead of the inclusive bound (`<= toUtc`) mandated by ADR-0001. Because the vendor batches all records with a single timestamp that lands exactly on the window's upper bound, the exclusive comparison silently dropped the entire night's batch.

## Timeline (UTC)
- 2026-08-19 12:57:16 — metric alert: `records_processed` = 0 (expected 150–400)
- Committed at 2026-08-19: revert of PR #4 ("fix/records-processed-boundary-condition"), which re-introduced the exclusive upper bound bug

## Impact
One nightly reconciliation batch was silently skipped. No records were processed for that batch. The exact number of records lost depends on the vendor batch size, but ADR-0001 notes that this can affect an entire night's worth of records (estimated 150–400 based on metric baseline).

## Root Cause
In `app/src/ReconciliationJob/RecordStore.cs`, line 36, the `GetRecordsForWindow()` method used `r.TimestampUtc < toUtc` (exclusive upper bound). ADR-0001 explicitly requires both bounds to be inclusive (`>=` and `<=`) because the vendor's nightly batch export stamps every record with the batch's cutoff time, which lands exactly on the window's upper bound. An exclusive comparison silently discards the entire batch.

## Detection
Metric alert on `records_processed` from simulated-app-insights observed value of 0 at 2026-08-19T12:57:16.443Z.

## Resolution
Changed line 36 of `RecordStore.cs` from `r.TimestampUtc < toUtc` to `r.TimestampUtc <= toUtc` to enforce inclusive bounds on both ends as required by ADR-0001.

Added a regression test `GetRecordsForWindow_IncludesRecordsAtUpperBound()` in `RecordStoreTests.cs` that explicitly validates that records with timestamps equal to the upper bound are included in the result set.
