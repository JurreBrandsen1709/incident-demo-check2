# Post-Incident Review: records_processed metric dropped to 0

## Summary
The reconciliation job reported 0 records processed when 150-400 records were expected. The root cause was an exclusive upper-bound comparison in `RecordStore.GetRecordsForWindow()` that violated ADR-0001, silently dropping records with timestamps exactly at the window's cutoff time. This is particularly critical because the upstream vendor batches all records in a nightly export with a single timestamp at the batch cutoff, causing an entire night's batch to be excluded. The fix changed the upper bound comparison from `<` to `<=`, restoring inclusive boundary semantics as specified in ADR-0001.

## Timeline (UTC)
- 2026-08-19T08:29:29.106Z — Metric anomaly detected: records_processed = 0, expected 150-400

## Impact
Complete loss of one night's reconciliation data (150-400 records). The reconciliation job failed silently without processing any records, which could have led to unreconciled transactions if not detected by the metric alert.

## Root Cause
A refactoring change to `RecordStore.cs` (commit 90b17c5) inadvertently changed the upper-bound comparison from `<=` to `<` in the `GetRecordsForWindow()` method. This violated ADR-0001 which explicitly requires inclusive boundaries on both ends:

```csharp
// Before fix (incorrect):
.Where(r => r.TimestampUtc >= fromUtc && r.TimestampUtc < toUtc)

// After fix (correct):
.Where(r => r.TimestampUtc >= fromUtc && r.TimestampUtc <= toUtc)
```

The vendor's nightly batch export stamps all records in the batch with the batch's cutoff timestamp. This cutoff timestamp lands exactly on the window's upper bound. An exclusive upper-bound comparison (`<`) excludes records with timestamps equal to the bound, silently dropping the entire night's batch.

## Detection
Metric alert on `records_processed` anomaly: observed value 0 vs. expected range 150-400.

## Resolution
Restored inclusive upper-bound semantics by changing the `<` operator to `<=` in `RecordStore.GetRecordsForWindow()` to comply with ADR-0001.
