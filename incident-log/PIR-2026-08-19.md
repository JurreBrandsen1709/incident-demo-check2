# Post-Incident Review: Insufficient Test Coverage for Date Range Boundaries

## Summary
A regression in `RecordStore.GetRecordsForWindow()` revealed incomplete test coverage for boundary conditions. While the code correctly implements inclusive bounds on both ends as required by ADR-0001, test coverage only validated the upper boundary. The vendor's batch export timestamps land exactly at window boundaries, making lower-boundary inclusion equally critical. Added comprehensive regression tests to validate both boundaries and the specific vendor batch scenario.

## Timeline (UTC)
- 2026-08-19T08:47:35.534Z — Metric anomaly detected: records_processed = 5, expected 150-400

## Impact
Test gap exposed that could have allowed a lower-boundary regression to reach production undetected. Existing tests provided insufficient coverage to catch changes to lower-bound semantics.

## Root Cause
The test suite in `RecordStoreTests.cs` included a test for records at the upper boundary (`GetRecordsForWindow_IncludesRecordAtUpperBoundary()`) but was missing:
1. A test for the lower boundary being inclusive (to catch `>` instead of `>=`)
2. A test for the specific vendor batch scenario where all records in a batch share the exact cutoff timestamp

This asymmetric coverage left the implementation vulnerable to regression on the lower bound, violating the ADR-0001 requirement that both bounds be inclusive.

## Detection
Code review of test coverage identified the gap. The production code already has the correct inclusive bounds (`>=` and `<=`), but test coverage was insufficient to detect regressions.

## Resolution
Added two new regression tests:
1. `GetRecordsForWindow_IncludesRecordAtLowerBoundary()` — validates the lower bound is inclusive
2. `GetRecordsForWindow_IncludesBoundaryBatchWithAllRecordsAtCutoff()` — validates the vendor batch scenario where all records have the same timestamp at the window boundary
